# サブエージェント委譲規約（常時適用）

**原則: 自分で抱え込まず、既定で専門エージェントに委譲する。**

Cursor では `Task` ツールで、Claude Code では `Agent(...)` または `--agent` で委譲する。

## ルーティング表

| 作業の種類 | 担当エージェント | 発火タイミング |
|-----------|----------------|--------------|
| Controller / Model / Middleware / FormRequest / ルート実装 | `laravel-backend` | バックエンドロジックを追加・変更するとき |
| Blade / Tailwind / Alpine.js 画面実装 | `frontend-blade` | 画面・UI・スタイルを追加・変更するとき |
| Pest テスト作成・実行・失敗解析 | `pest-tester` | 実装変更後、テスト追加・テスト失敗修正のとき |
| コードレビュー（品質・可読性・バグ） | `code-reviewer` | コード変更後（実装終了時）に必ず実行 |
| UI/UX レビュー（デザイン・a11y・一貫性） | `ui-reviewer` | Blade/CSS/JS 変更後に必ず実行 |
| セキュリティ監査（ACL・入力・機密） | `security-auditor` | 認可・権限・ユーザー入力に触れた変更後に必ず実行 |
| マイグレーション・スキーマ変更 | `db-migrator` | テーブル追加・カラム変更・リレーション変更のとき |
| README / SETUP / コメント / PR 説明 | `docs-writer` | 仕様変更・新機能追加後のドキュメント整備のとき |
| 多工程の機能開発全体を統括 | `commander` | 複数エージェントの協調が必要な大きめの機能追加のとき |

## 委譲の原則

1. **並行投下**: 依存がない作業（例: backend 実装と frontend 実装）は同時に委譲する。
2. **順序厳守**: `実装 → テスト → レビュー/監査` の順を崩さない。テストなし・レビューなしで完了としない。
3. **同時編集禁止**: 同一ファイルを複数エージェントに同時編集させない（コンフリクト防止）。
4. **ACL 最優先**: 認可に触れる変更は必ず `security-auditor` を通す。

## 委譲しないケース

- 1行コメント追加・typo 修正など影響範囲が極小の変更
- 既存テストの確認のみ（実行して確認するだけ）
