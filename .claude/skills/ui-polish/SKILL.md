# UI ポリッシュ（磨き込み / deslop）

このプロジェクトの **Blade + Tailwind CSS 3** 画面を、既存のトーンを壊さずに洗練させるためのパス。
ゼロから派手に作り直すのは `frontend-design` スキルの役割。こちらは **今ある画面の質を底上げ**することに徹する。

## 原則

- **既存トーン維持**: 新しい色・フォント・派手な装飾を勝手に増やさない。すでに使われている Tailwind クラスの語彙に揃える。
- **一貫性 > 個別最適**: 似た要素は同じ間隔・同じ角丸・同じ影で揃える。バラつきを消すことが磨き込みの本体。
- **削る勇気**: 装飾・枠線・影を「足す」より「減らす・統一する」方が効くことが多い。

## チェックする5観点

### 1. 間隔（Spacing）
- Tailwind の間隔スケール（`p-2/3/4/6/8`, `gap-*`, `space-y-*`）に統一。中途半端な任意値（`p-[13px]`）を避ける。
- セクション間は広く、関連要素間は狭く（近接の法則）。`space-y-*` で縦リズムを揃える。
- カード/コンテナの内側パディングを画面内で統一（例: カードは `p-6` で統一）。

### 2. 視覚階層（Hierarchy）
- 重要度を「サイズ・ウェイト・色」で表現。見出し `text-xl font-semibold`、本文 `text-sm/base text-gray-700`、補助 `text-xs text-gray-500` のように段を作る。
- 1画面に同格の強い要素を並べすぎない。主役（primary action）は1つ。
- プライマリ/セカンダリボタンの強弱を既存コンポーネント（`x-primary-button` / `x-secondary-button`）で表現する。

### 3. タイポグラフィ
- 行長は長すぎない（本文は `max-w-prose` 目安）。行間は `leading-relaxed` 等で読みやすく。
- フォントサイズの種類を絞る（4〜5段程度）。`text-gray-*` の濃淡で情報の強弱をつける。

### 4. 整列とリズム（Alignment）
- 左端・グリッドを揃える。ラベルと値、アイコンとテキストの縦位置を `flex items-center` で合わせる。
- 一覧は `divide-y divide-gray-100` などで等間隔の区切りを作る。

### 5. 角丸・影・境界線
- 角丸（`rounded-lg` 等）・影（`shadow-sm`）・枠線（`border border-gray-200`）を画面内で統一。混在させない。
- 影と枠線は二重にしない（どちらか一方で十分なことが多い）。

## 進め方

1. 対象 Blade を読み、上記5観点で「揃っていない点」を洗い出す。
2. 既存で多数派のクラス語彙に寄せて統一する（少数派を多数派へ）。
3. 出力は `{{ }}` エスケープを保ち、機能・文言・ACL 表示制御（`@can`）は変えない。
4. レスポンシブ（`sm: md: lg:`）が崩れていないか確認。`.claude/rules/blade-frontend.md` を厳守。
5. 仕上がりは `ui-reviewer` でのレビュー、表示確認は `webapp-testing` を提案してよい。

アクセシビリティ（コントラスト・ラベル）は `accessibility` スキル、演出は `ui-motion` スキルに委ねる。
