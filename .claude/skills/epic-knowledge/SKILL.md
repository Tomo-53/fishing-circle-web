# エピック知識（完了するたびに賢くなる仕組み）

静的な規約（グローバル `CLAUDE.md` / 領域 `.claude/rules/`）に加えて、**案件ごとに動的な知識を蓄積**する。
タスクを完了するたびに「決定事項・前提・学び・未解決事項」を案件ノート `.claude/epics/<slug>/_epic.md` へ昇格し、個別タスクは消えても知識は永続化する。

## 1. 文脈の読み込み（3階層）

作業前に上から順に読む。

1. **グローバル**: ルート `CLAUDE.md`（全共通ルール）
2. **領域**: `.claude/rules/`（ファイル種別規約）＋ 作業対象の `src/**/CLAUDE.md`
3. **案件**: 該当する `.claude/epics/<slug>/_epic.md`（この案件の全記録）

案件が複数ある/不明なときは、現在の `feature/` ブランチ名に対応する slug を優先する。該当が無ければ `/epic-new` で作成する。

## 2. 知識の昇格（タスク完了時）

タスクが完了したら、archive せずに次を行う。

1. **抽出**: 直近の会話・差分（`git diff`）・タスクファイルから次を抜き出す。
   - **決定事項**: 何を・なぜそう決めたか（後から意図が追える形）
   - **前提**: 依存している事実・制約・環境
   - **学び**: ハマりどころ・再利用できるノウハウ
   - **未解決事項**: 次にやるべきこと・保留中の判断
2. **追記**: `_epic.md` の該当セクションへ追記する（既存記述と重複・矛盾しないよう統合。古い決定が覆ったら更新する）。
3. **タスク履歴**: 「タスク履歴」に1行記録する（日付 + 番号 + 要点）。
4. **整理**: 完了した `tasks/NNN-*.md` は削除してよい（要点は `_epic.md` に昇格済みであること）。
5. **状態更新**: エピック全体が終わったら `状態` を「完了」にする。

重要な情報を昇格せずにタスクファイルだけ消すのは禁止（知識ロストになる）。

## 3. 次タスクの提案（わんこそば配膳）

`/next` では `_epic.md` の「未解決事項」と現状（ブランチ・差分）を読み、**次にやるべきことを 1 つだけ**具体的に提案する。
ユーザーが「やる/OK」と返したら着手し、完了したら 2. の昇格を行う。提案は小さく実行可能な単位にする。

## 4. セキュリティ（必須）

案件ノートは Git 管理に乗りチームで共有される。`.claude/rules/security.md` に従い、以下は**書かない**。

- 個人情報（実名・連絡先）
- 釣果の正確な座標・保護対象のポイント情報
- `.env` の値・`APP_KEY`・パスワード・APIキー等の認証情報

値は伏せ、「環境変数で管理」「座標は非公開」のように記録する。
